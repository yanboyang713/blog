[AWS]({{< relref "20230314144515-aws.md" >}}) Compute is the AWS service area for running application code and processing workloads. It includes virtual machines, containers, serverless functions, managed application platforms, lightweight VPS-style hosting, and large-scale batch processing.

The main design choice is how much infrastructure control you need. EC2 gives the most direct control over hosts and operating systems, containers provide a portable application runtime, Lambda removes most server management, and managed platforms such as Elastic Beanstalk and Lightsail trade flexibility for simpler operations.


## Core services {#core-services}

-   [AWS EC2]({{< relref "2023-10-28-183931-aws_compute.md" >}}) - virtual machines with direct control over instance type, operating system, storage, networking, scaling, and pricing model.
-   [Amazon Elastic Container Service (ECS)]({{< relref "2023-10-28-203025-amazon_elastic_container_service_ecs.md" >}}) - container orchestration for running and scaling containerized applications.
-   [AWS Fargate]({{< relref "2025-09-09-151701-aws_fargate.md" >}}) - serverless compute for containers, often used with ECS when you do not want to manage EC2 capacity.
-   [AWS Lambda]({{< relref "2023-10-28-204435-aws_lambda.md" >}}) - event-driven functions that run code without provisioning or managing servers.
-   [AWS Elastic Beanstalk]({{< relref "2023-10-28-205733-aws_elastic_beanstalk.md" >}}) - managed application deployment that provisions and operates underlying AWS resources for web applications.
-   [AWS Batch]({{< relref "2023-10-28-210531-aws_batch.md" >}}) - managed batch job queues and compute environments for large-scale batch processing.
-   [Amazon Lightsail instances]({{< relref "2023-10-28-204914-amazon_lightsail_instances.md" >}}) - simplified VPS-style compute for small applications, prototypes, and predictable hosting needs.
-   [Amazon Lightsail databases]({{< relref "2023-10-28-205201-amazon_lightsail_databases.md" >}}) - simplified managed databases often paired with Lightsail instances.


## Choosing a compute option {#choosing-a-compute-option}

-   Use [EC2]({{< relref "2023-10-28-183931-aws_compute.md" >}}) when you need host-level control, custom networking, custom operating system configuration, or specialized instance families.
-   Use [ECS]({{< relref "2023-10-28-203025-amazon_elastic_container_service_ecs.md" >}}) or [Fargate]({{< relref "2025-09-09-151701-aws_fargate.md" >}}) when the application is packaged as containers and should scale as services or tasks.
-   Use [Lambda]({{< relref "2023-10-28-204435-aws_lambda.md" >}}) for short-lived, event-driven workloads where server management is unnecessary.
-   Use [Elastic Beanstalk]({{< relref "2023-10-28-205733-aws_elastic_beanstalk.md" >}}) when you want to deploy application code quickly while AWS manages the supporting compute, load balancing, scaling, and monitoring.
-   Use [AWS Batch]({{< relref "2023-10-28-210531-aws_batch.md" >}}) for queued jobs, dependency-driven workflows, and large compute runs that can scale dynamically.
-   Use [Lightsail]({{< relref "2023-10-28-204914-amazon_lightsail_instances.md" >}}) for simple projects where predictable pricing and low operational overhead matter more than deep AWS customization.
